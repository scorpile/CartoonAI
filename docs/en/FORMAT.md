# Project format v2 (engine `celstudio/v2`)

A v2 project is a folder under `projects/<id>/`. The **source of truth** is `script.json` (the script as data).
`film.json` is the compiled result (keyframes already computed); it is not edited by hand.

```
projects/taller-v3/
  script.json            declarative script (you edit this)
  script.previous.json   copy of the previous version (created by save())
  film.json              compiled, schema 2 (read by the engine)
  characters/luma.json   rig of each character
  sets/valley.json       set
  assets/                images: assets/<character>/, assets/sets/<set>/, assets/props/<prop>/
  refs/                  uploaded references
  papelera/              JSON of characters and sets removed from the library (nothing is ever deleted)
  renders/               videos
```

All paths are relative to the project folder, must exist and cannot leave it.

Commands:

```
python -m celstudio.v2 compile projects/taller-v3     # script.json -> film.json (JSON summary; error and exit code 1 if invalid)
python -m celstudio.v2 render projects/taller-v3/film.json --output out.mp4
python work/v3/build_film.py                          # regenerates the pilot (in scene form): writes script.json and compiles
```

Python API (`celstudio/v2/project.py`): `load(root)`, `compile_script(script, root)`, `check(script, root)` (list of
`{"path", "message"}`, empty if valid), `save(root, script, expect_revision=None)`, `catalogue()`, `expand(script)` (flat form of a script with scenes), `group_scene(script, ...)` (the inverse, for generation scripts) and `usage(script, kind, id)` (where a library element is used). Errors are
`ScriptError` with `.path` (for example `shots[2].actions[14]`) and a message (localised: Spanish or English, see the API `?lang=` parameter).

## Characters (`characters/<id>.json`)

They are generated by `work/v3/build_rig.py` from the measured parts in `assets/<id>/rig.json`; normally they are not written by hand.
Main fields (world units: 1280x720, character at scale 1):

| Field | Meaning |
|---|---|
| `name`, `colors` | Name and palette (`outline`, `skin`, `eye_white`, `pupil`, `mouth_inside`, `tongue`, `blush`, `sleeve`, `cuff`...) |
| `outline` | Outline thickness |
| `hip_height`, `hip_half`, `hip_joint_dy`, `ankle_h` | Hip height above the ground, half the distance between the feet, leg adjustments |
| `foot` | `toe`, `heel`, `depth`: foot geometry for stepping |
| `arm`, `leg` | Lengths (`upper`/`fore`, `thigh`/`shin`), widths per segment `w`, `smooth`, colour bands (`bands`), cuff (`cuff`), highlights |
| `torso`, `hips` | Image (`file`), scale `upp` (units per pixel), `pivot`; the torso adds `shoulder` and `neck`; `"merge": false` on a torso drawing stops the engine from covering the arm root with the torso colour (useful when the shoulder clothing is not the colour of the sleeve) |
| `hands` | One image per hand pose (`closed`, `open`, `point`...), with `upp`, `pivot` (centre of the wrist cut) and `dir` (where the fingers point). The main drawing is the palm; `back`, optional and with the same fields, is the back of the hand. In both, the thumb is a quarter turn counter-clockwise from the fingers. The engine picks the side and the mirroring by anatomy |
| `boots` | Boot image per view (`side`...) and its mouth where the leg enters |
| `head` | `front` and `3q` views: image, mask, `size`, `upp`, `pivot`, face (`eye_*`, `brow_*`, `blush_*`, `mouth`, `bbox`) and appendages (`ear_l`, `antenna`...: `base`, `tip`, `freq`, `damp`, `gain`) |
| `items` (optional) | Objects held in the hand: `{"fork": {"file", "upp", "pivot", "dir", "rot"?, "front"?}}`. The channel `item_l` / `item_r` picks the object (`""` = empty hand). It is drawn in hand space, on the hand's `grip` point (if the hand has none, its `pivot`), with the object's `dir` axis towards the thumb side; behind the hand unless `"front": true`, so a gripping hand with a gap wraps around it. It follows the layer and the mirroring of the arm |
| `wear` (optional) | Garments over the torso: `{"bib": {"front": {...}, "profile": {...}, "back3q": {...}}}` with `file`, `upp`, `pivot` and `at` (position of the pivot relative to the torso's `neck` point). The `wear` channel picks the garment; it deforms with the torso (curve, turn, hem) and is absent in views without a drawing |
| `defaults` (optional) | Default channel values for that character |

Front layers between actors: a layer with `"front": true` covers all actors; if it also has `"order": N`, it is drawn after the actors with `order` < N and before the rest (the blanket covers only whoever sleeps under it, the door frame only whoever crosses it). A shot can change it with `"layer_order": {"<layer id>": N}`. An actor's order can also be animated with keys on the `order` channel (with `ease` `step`), which takes precedence over its fixed `order` field: that way a character passes in front of a door frame while walking along the path and behind it when crossing the threshold.

Per-eye channels: `lid_l` and `lid_r` are added to `lid` (with `lid` 1 and `lid_r` -1 the character sleeps with one eye open).

The anchor points used by props (`tip_antenna`, `tip_ear_r`) come from the head's appendages.

## Sets (`sets/<name>.json`)

`work/v3/valley_set.py` generates `sets/valley.json`. Keys:

| Key | Content |
|---|---|
| `color` | Background colour |
| `ground_y` | Ground line (world y; actors use `y` = ground) |
| `layers` | Image layers, far to near: `id`, `image`, `x`, `y`, `w` (width in world units), `depth` (parallax: `.03` almost fixed, `1.0` = actors' plane, `>1` foreground), `blur` (depth-of-field blur), `front` (drawn in front of the actors), `opacity`, `drift` (`vx`, `wrap`: drifting clouds), `sway` (`deg`, `period`, `phase`, `anchor`: swaying) |
| `lights` | Soft lights: `x`, `y`, `depth`, `radius`, `color`, `opacity`, `pulse`, `period`, `flicker`, `front` |
| `smoke` | Smoke: `x`, `y`, `depth`, `rate`, `rise`, `life`, `size`, `drift`, `opacity` |
| `particles` | `kind` (`motes`, `leaves`), `count`, `area` [x0,y0,x1,y1], `depth`, `color`, `size`, `opacity`, `speed` |
| `rays` | Light rays: origin, `count`, `length`, `spread_deg`, `direction_deg`, `color`, `opacity` |
| `light` | Character lighting: `ambient` (`color`, `amount`), `rim` and `shade` (`dir`, `color`, `opacity`, `width`), `shadow` with `contact` (ellipse on the ground) and `cast` (projected shadow: `shear`, `squash`, `blur`...) |
| `post` | `bloom`, `grade` (contrast, saturation, temperature, lift, gain), `vignette`, `grain` |

The compiler copies each set into `film.json`. If a shot needed its own `light` or `post`, there is currently no verb for it.

## Props (`props` in `script.json`)

A library of named props: `props.<name>` is the specification of a sprite sheet. Fields: `sheet` (image),
`cells` (boxes `[x0,y0,x1,y1]` of each frame), `pivot`, `upp`, `layer` (`front`), `shadow` (`ground`, `width`), default `id`.
In a shot it is placed with `{"id": "butterfly", "prop": "butterfly", "spec": {...}}`: `spec` is merged over the library (for example `anchor`: `{"actor": "pip", "point": "tip_antenna", "dx": 2, "dy": -3}` sticks the prop to a point of the character when
its `attach` channel is 1). Usual prop channels: `x`, `y`, `scale`, `rot`, `opacity`, `frame`, `facing`, `attach`, `shadow`.
The dust clouds of `puff_burst` use the library prop `puff` and get ids `puff<t>-<i>`.

## Library and scenes

Three levels: **library** (project) → **scene** → **shot**.

- The **library** is the `characters`, `sets` and `props` of the script: what exists in the film.
- A **scene** (`scenes`, optional list) chooses a set, a **cast** (instances of library characters; there can be several of the same character with different ids) and the available props. The cast's `start` holds the scene's default values.
- A **shot** belongs to a scene (`scene`) and uses a subset of its cast and props. Film order is the order of `shots`, so scenes can alternate; the order of `scenes` is organisational only.

```json
"scenes": [{"id": "workshop", "title": "The workshop at sunset", "description": "...", "set": "valley",
  "cast":  [{"id": "luma", "character": "luma", "start": {"y": 690.0, "scale": 0.66}},
            {"id": "pip",  "character": "pip",  "start": {"x": 838, "y": 690.0, "scale": 0.66}}],
  "props": [{"id": "butterfly", "prop": "butterfly", "spec": {}}]}],
"shots": [{"id": "s02", "scene": "workshop", "duration": 3.8, "description": "...",
  "actors": [{"id": "pip", "start": {"facing": 1}}], "props": [], "actions": []}]
```

Rules: `actors[i].id` is a cast id and its `start` is merged key by key over the scene's (the shot's wins); `character` is inherited and is not changed in the shot. The same for props (shot `spec` over scene `spec` over library; shallow merge). Verbs that use the library directly (`puff_burst`) do not need the prop to be in the scene. Scripts without `scenes` (shots with their own `set` and cast) keep working the same and both forms can be mixed. `expand()` turns the scene form into the flat one and `compile_script` compiles that form, so both give the same `film.json`.

Scenes are validated with a path (`scenes[1].cast[0]`, `shots[3].actors[1]`): unknown scene, unknown set/character/prop, duplicate ids (cast and props share the id space), an actor or prop that is not in the scene, an unknown channel in `start`, a scene without `set`, a shot with both `scene` and `set`.

**Library operations** (done by the server on disk; they return the changed element and the new `revision`; the page merges them into its script without losing unsaved edits and without a revision conflict, like reference uploads):

- *Import* from another film in `projects/`: copies the JSON and every image it references to `assets/<id>/`, `assets/sets/<id>/` or `assets/props/<id>/`, rewrites the paths (the copy is self-contained) and picks another id (`id-2`) on collision.
- *Duplicate* inside the project with another id (a set with different light or fewer layers is a legitimate new set).
- *Empty set* (flat colour, no layers) to which layers are uploaded (`assets/sets/<id>/`) and reordered; *new prop* with an uploaded sheet (`cells`, `pivot`, `upp` are adjusted in its JSON).
- *Remove*: refused if any scene or shot uses it (it says where; it also checks the browser's unsaved script). It only retires it: the JSON of a character or set moves to `papelera/` and the images stay.
- *New film*: `projects/<id>/` with a minimal valid script (empty libraries, no scenes or shots).
- Creating a new character from art is not done in the app: it requires `work/v3/prep_parts.py` and `build_rig.py`.

## Series and episodes

A project can be a **standalone film** (`projects/<id>/script.json`, everything above) or a **series**: a shared library with many episodes. Scripts belong to episodes; everything in the library can be used from any of them. A folder with `series.json` is a series; one with `script.json` and no `series.json` is a film (compatible without changes).

```
projects/my-series/
  series.json              id, title, revision, notes, bible, style, fps/width/height, references, library
  characters/<id>.json     rigs (paths relative to the series root)
  sets/<id>.json           sets
  assets/<id>/  assets/sets/<id>/  assets/props/<id>/   library images
  refs/  papelera/         uploaded references; removed elements and episodes (nothing is ever deleted)
  episodes/ep01/
    script.json            episode script: title, notes, story, scenes, shots (no library of its own)
    film.json              compiled; includes "root": "../.." (the assets root, relative to its folder)
    renders/               episode videos
```

`series.json`: `{"schema_version": 2, "kind": "series", "id", "title", "revision", "notes", "bible", "style", "fps", "width", "height", "references": [], "library": {"characters": {id: path}, "sets": {id: path}, "props": {id: specification}}}`. Asset paths are relative to the **series root**, not to the episode's.

- **Effective library** of an episode = the series library + an optional local block `characters` / `sets` / `props` in its `script.json`, for elements that exist only in that episode (the local one wins if the id matches; `project.warnings()` and the app warn about it). `fps`, `width`, `height`, `style` and `bible` are inherited from the series if the episode does not define them; the series' `references` are added to the episode's.
- `project.load(<episode folder>)` returns the effective script (with the library merged) and `project.save()` stores it without copying the series library into the episode. `compile_script` / `check` / `save` accept the episode folder (`projects/<series>/episodes/<ep>`); the compiled output includes only the elements the episode uses, so a broken element nobody uses does not break the other episodes. `Stage` / `load_film` read `root` from `film.json`; rendering is the same.
- **Scenes** still belong to the episode (set + cast + props + their shots). `project.import_scene(target, source, id, new_id)` copies a scene and its shots from another episode (or the same one, to duplicate it); colliding ids get a suffix (`id-2`) and missing local elements from the source are copied into the local block.
- `project.usage_table(script)`, `series_usage(root)` (which episodes, scenes and shots use each character, set and prop), `usage_in_series` and `library_catalogue(root, q, kind, used, episode, limit, offset)` (compact listing, filterable and paginated for hundreds of elements).
- Removing an element from the series library is refused while any episode uses it (the message names the episodes). Deleting an episode moves its folder to `papelera/episodes/`.

Commands:

```
python -m celstudio.v2 new-series my-series --title "My series"       # projects/my-series/series.json with an empty library
python -m celstudio.v2 new-episode my-series ep01 --title "Pilot"     # projects/my-series/episodes/ep01/
python -m celstudio.v2 compile projects/my-series/episodes/ep01       # (or .../script.json) -> the episode's film.json
python -m celstudio.v2 render projects/my-series/episodes/ep01/film.json --output out.mp4
python -m celstudio.v2 series-convert projects/<film>                 # standalone film -> series with episode ep01
```

`series-convert` moves the library into `series.json` and the script into `episodes/ep01/` (also `renders/`), and recompiles; it deletes nothing else.

API (`/api/v2`): `GET films` lists films (`kind` `film`) and series (`kind` `series`, with `episodes` and `library`). An episode is directed like a film with `films/<series>/episodes/<ep>/...` and supports the same actions (`GET`/`POST` of the script, `check`, `frame`, `preview`, `pose`, `setframe`, `characters/<id>`, `sets/<id>`, `upload`, `render`, `importable`, `library/*`); in addition `POST films/<series>/episodes/<ep>/scenes/import` `{episode, scene, as?, script?}` returns the scene, its shots and the local elements to add (it writes nothing). In an episode, library operations (`library/import|duplicate|remove|set|prop`) act on the series library. Series: `POST series` (create), `GET|POST series/<id>` (title, notes, bible, episodes), `GET series/<id>/library?q=&kind=&used=&episode=&limit=&offset=`, `GET series/<id>/usage?kind=&id=`, `GET series/<id>/importable`, `GET series/<id>/pose|setframe`, `POST series/<id>/library/<op>`, `POST series/<id>/upload` (layers and sheets), `POST series/<id>/episodes` (create) and `POST series/<id>/episodes/<ep>/duplicate|rename|delete` (`delete` requires `confirm` equal to the id).

App: the project selector groups "Series" and "Films". Inside a series the episode selector appears with two views: **Episodes** (create, open, duplicate, rename, delete with confirmation; series title, notes and bible) and **Series library** (search, filters by kind, use and episode, thumbnails, episodes that use each element, duplicate, remove if unused, import from other series or films). The other views (references, script, characters, sets, scenes, shots, render) work on the open episode; library changes are saved in the series. The Scenes view can import or duplicate a scene from another episode.

The web studio is bilingual (Spanish / English, selector in the header); backend messages follow the `?lang=` parameter or the `Accept-Language` header.

## References

`references` (a list, currently empty) is reserved for reference images or notes; the engine and the compiler ignore it.

## Script (`script.json`)

Top-level fields: `schema_version` (2), `kind` ("script"), `id`, `title`, `revision` (bumped by `save()`), `fps`, `width`,
`height`, `story` (free text), `style` (`hold`, `contour`, `boil`, `boil_hold`: drawing on twos, line thickness, jitter), `bible`
(style, story, continuity), `characters` (id -> path), `sets` (name -> path), `props`, `references`, `scenes` (optional), `shots`.

Each shot:

```json
{"id": "s01", "duration": 6.0, "set": "valley", "description": "...",
 "actors": [{"id": "luma", "character": "luma", "start": {"x": -60, "y": 690, "scale": 0.66, "look_x": 0.55}}],
 "props":  [{"id": "butterfly", "prop": "butterfly", "spec": {"anchor": {"actor": "pip", "point": "tip_antenna"}}}],
 "actions": [
   {"on": "shot",  "do": "cam",  "t": 0, "x": 612, "y": 388, "zoom": 1.04},
   {"on": "luma",  "do": "walk", "t0": 0.7, "t1": 7.4, "x0": -70, "x1": 482, "scale": 0.66, "step": 56, "lift": 14},
   {"on": "butterfly", "do": "path", "t0": 3.0, "t1": 6.6, "points": [[400, 330], [520, 440]], "flutter": 6, "seed": 1.3}]}
```

- `duration` in seconds (rounded to frames). `set` is a key of `sets` (a shot in a scene carries no `set`: it uses the scene's).
- `actors[].start`: channel values at t=0. Valid channels are those in the list below (`catalogue()["channels"]`).
- Actor and prop ids are unique within the shot; `shot` is reserved.
- `actions` is an **ordered list** per shot: order matters because some verbs read what was written before (`to` starts from the current value,
  `track` reads the prop's trajectory, `pulse` returns to the previous value).
- `on` is `"shot"`, an actor or a prop; `do` is the verb; the other keys are named arguments. Verbs with
  `*args` (`blink`) take a list: `{"on": "pip", "do": "blink", "times": [3.8, 4.05]}`.
- Verbs marked "+ channels" also accept any character channel as an argument (`{"do": "to", "t": 1, "dur": 0.3, "lean": 5, "head_rot": -3}`).
  A text value (`"open"`, `"point"`) is applied at once.
- Valid curves (`ease`) and expressions (`face`) come from `catalogue()["eases"]` and `catalogue()["expressions"]`.

Character channels: position/scale (`x`, `y`, `scale`, `facing`, `lift`), body (`hip_dx`, `hip_dy`, `lean`, `bend`, `body_yaw`,
`torso_sx/sy`), head (`head_rot`, `head_dx/dy`, `face_x/y`, `look_x/y`), face (`smile`, `mouth_open`, `mouth_w`, `mouth_round`,
`brow_y`, `brow_rot`, `eye_open`, `squint`, `lid`, `pupil`, `blush`), arms (`arm_l_x/y`, `arm_r_x/y`, `arm_*_bend`, `hand_*_rot`,
`hand_l`, `hand_r`, `shoulder_*_dy`), legs (`foot_*_x/y/rot/roll`, `knee`), `life` (breathing), `opacity`, `shadow`. `arm_*_x/y` and
`foot_*_x` start from values derived from the rig (arm reach, foot separation).

### Verbs

Parameters with `=value` are optional (default value); `*` marks a list of values. Table generated with `project.catalogue()`
(the descriptions are written by hand). If verbs are added, the parameter column must be regenerated with that function.

| Target | Verb | Parameters | What it does |
|---|---|---|---|
| actor | `auto_blink` | enabled=true | Turns automatic blinking on or off |
| actor | `blink` | times* | Blinks at the given instants |
| actor | `face` | t, name, dur=0.22, ease="soft" + channels | Moves to an expression from `EXPRESSIONS`; extra channels touch it up |
| actor | `gasp` | t, amount=1.0 | Sudden intake of breath |
| actor | `hop` | t, height=22, air=0.34, squash=1.0 | Jump with anticipation and landing (lands at t+0.19+air) |
| actor | `key` | t, channel, value, ease="smooth" | Direct keyframe on a channel |
| actor | `laugh` | t, dur=1.4, beats=5, strength=1.0 | Shoulder and torso bounce while laughing |
| actor | `look` | t, x, y=0.0, dur=0.1, head=0.0 | Gaze (-1..1); `head` drags the head along |
| actor | `look_at` | t, target, x, facing, dur=0.1, head=0.45 | Looks at a world point `[x, y]` from position `x` |
| actor | `nod` | t, count=2, depth=9, period=0.34 | Nod |
| actor | `pulse` | t, up=0.15, hold=0.1, down=0.3, ease="out", back="inout" + channels | Goes to the values and returns to the previous ones |
| actor | `set` | t + channels | Values at once (no interpolation) |
| actor | `to` | t, dur=0.4, ease="inout", overlap=1.0 + channels | Holds the value until t and arrives at the target after `dur` (with a delay per channel family) |
| actor | `track` | prop, t0, t1, x, facing, step=0.14, head=0.5 | Eyes and head follow a prop (its id) |
| actor | `turn_around` | t, facing | Turn through the front view and change of `facing` |
| actor | `walk` | t0, t1, x0, x1, scale=1.0, step=46, duty=0.6, lift=15, swing=17, ease=0.22, phase=0.0, bob=2.6, lean=4.0, strike=16, push=34, drop=5.0 | Walk with planted feet from x0 to x1 |
| actor | `wave` | t, side="l", cycles=3, period=0.36, out=-78, up=-50 | Wave with arm `l` or `r` |
| prop | `flap` | t0, t1, rate=9.0, frames=[0, 1, 2, 1] | Wing cycle through sheet frames |
| prop | `key` | t, channel, value, ease="smooth" | Keyframe on a channel |
| prop | `path` | t0, t1, points, flutter=5.0, seed=0.0, facing=true | Flight through world points (Catmull-Rom) with flutter |
| prop | `perch` | t0, t1, period=1.5 | Slow wing breathing at rest |
| prop | `to` | t, dur, ease="inout" + channels | Interpolates prop channels |
| shot | `cam` | t, x=null, y=null, zoom=null, ease="inout" + extras | Camera key (`x`, `y`, `zoom` and extras such as `shake`) |
| shot | `dof` | value | Depth of field: a number or keys `[[t, value, ease?], ...]` |
| shot | `fade_in` | dur=0.6, color="#000000" | Fade in from a colour |
| shot | `fade_out` | dur=0.8, color="#000000" | Fade out to a colour |
| shot | `overlay` | + extras | Free graphic layer (`kind`: `fade`, `title`...) with its keys |
| shot | `puff_burst` | t, x, y, direction=-1, count=3, spread=30, size=1.0 | Little dust clouds (requires the `puff` prop) |

The Python DSL in `celstudio/v2/direct.py` records every top-level verb call as an action with named arguments, and newer verbs (for example `drift`, `react`, `overshoot`, `wave_off`) may be missing from this hand-written table; `project.catalogue()` is the authoritative list.

## Validation

`check()` returns errors with a path (scenes too, see above) for: unknown verb or target, nonexistent character/set/prop, missing file or image,
missing or unexpected required argument, a time that is not a number, unknown curve or expression, duplicate ids and unknown
channels (in `start`, in `key` and in the arguments of `set`/`to`/`pulse`/`face`).

## Application

`python -m celstudio serve --open` (or `ABRIR_CEL_STUDIO.cmd` on Windows) opens the v2 studio at `http://127.0.0.1:8768/`.
Each folder `projects/<id>/` with a `script.json` (film) or a `series.json` (series, see "Series and episodes") appears in the selector. The logic is in `celstudio/v2/api.py` (routes `/api/v2/films/...`; library: `POST films`, `GET <id>/importable`, `POST <id>/library/{import,duplicate,remove,set,prop}`, `GET <id>/setframe`; `POST <id>/upload` accepts `category` `set_layer` or `prop_sheet` for layers and sheets).

| View | What it edits | Where it writes |
|---|---|---|
| (sidebar) | Film selector and "+ New film" | new `projects/<id>/` with a minimal `script.json` |
| References | Uploads images or text (style, character, set, script) and their notes; removing a reference only takes it off the list | `refs/` and `references` of `script.json` (the upload saves immediately) |
| Script | `title`, `story`, `bible`, `style` (fps and size are read-only) | `script.json` (Save button or Ctrl+S) |
| Characters | Import from another film, duplicate, remove; where each one is used; pose views, colours, proportions and rig JSON | `characters/<id>.json` (copy `<id>.previous.json`), recompiles `film.json`; import, duplicate and remove immediately save the library in `script.json` |
| Sets and props | Empty set, import, duplicate, remove; layers (upload, reorder, remove), lights, particles, `light`, `post`; `props` library (create with a sheet, import, duplicate, remove) | `sets/<id>.json` (with `.previous.json`); `props` in `script.json`; layers in `assets/sets/<id>/` |
| Scenes | Create, duplicate, delete (if no shot uses it) and reorder scenes; per scene: id, title, description, set with preview, cast (instances, default `start`) and props | `script.json` (`scenes`; saving validates and recompiles) |
| Shots | List with each shot's scene and a scene filter; "+ New" creates inside the filtered scene; who of the cast appears (checkbox + own `start`; unchecking an actor with actions warns and deletes them); ordered table of actions (targets: the shot, its actors and its props); preview of the unsaved script | `script.json` (saving validates, bumps `revision`, copies `script.previous.json` and recompiles `film.json`) |
| Render | The whole film or one shot, at a chosen width; progress, cancel and player | `renders/<jobid>-<shot|film>.mp4` (never overwrites) |

Saving with an old `revision` returns a conflict; saving a script with errors returns the path of the first error. Rendering uses the saved script.
